# 游戏小说

机制必须服务于人物决策：读者应明白角色为何这样操作、失误意味着什么。内容只使用原创游戏设定与叙事表达。

## 工作流

1. 选择叙事位置：职业赛事、业余社群、虚拟冒险或游戏开发；不要混成无规则的万能世界。
2. 写清核心循环、胜负条件、资源限制、信息不对称和观战者如何理解局面。
3. 读取 `references/blueprint.md`，把角色目标、战队关系和赛季/冒险节点对齐。
4. 比赛或副本按“计划—变数—调整—代价—赛后余波”呈现。
5. 检查是否让现实关系与游戏选择相互影响，避免只报技能名和数值。

## 可交付内容

- 原创游戏机制说明、战队关系表、赛季或副本大纲
- 一局比赛、团队复盘、招募冲突或终局决战场景
- 可读性诊断：解释读者在哪一步会看不懂或失去关切

## 边界

- 不使用现实游戏、赛事、职业选手或现成作品的专有内容。
- 不把游戏外挂、作弊或绕过安全机制写成可复用教程。
- 不仿写真实作者或复刻既有游戏小说的升级节奏。

规划时读取 `references/blueprint.md`；真正写正文、改文风或诊断节奏前，必须先读取 `references/craft.md`；写分章、连载或卡文修复时，读取 `references/chapter-engine.md`。
